# Working in this repository

- `standard/core.md` is the canonical reusable standard (keep <= 300 words; pinned at `0.2.0` independently of the `0.6.0` repo/tooling release in `VERSION`). Keep rationale, routing, and model-specific deltas in `docs/` and `gates/model_deltas.json`; do not duplicate them into standing instructions.
- Rule IDs (`R1`–`R7` and `D-*` deltas) are stable: retiring a rule leaves a gap; never renumber.
- This file governs repository maintenance. Do not load it into benchmark subjects. Run subjects in clean workspaces outside this repository with isolated `CODEX_HOME` and only their assigned condition, prompt and inputs.
- Keep vendor observations, external evaluations, proposed controls, archived pre-public diagnostics, and clean public measurements distinct. Four pre-public `n = 1` internal diagnostic pilots (`LOCAL-01`–`LOCAL-04`, 348 runs across `v0.2.0`–`v0.5.0`) informed gate and delta refinements (`v0.2.0` 96% baseline ceiling; `v0.3.0` `27/30 -> 28/30 -> 29/30`; `v0.4.0` real-work `13/20 -> 13/20 -> 15/20` with Fable `+23.9%` cost and `RW3` timeouts; `v0.5.0` 4-model `10/16 -> 13/16 -> 13/16`, or `8/16 -> 11/16 -> 13/16` under strict `wc -w`, with Opus `-18.4%` words at `-1.3%` USD) and were archived privately off the public repository because pre-public Codex runs lacked `CODEX_HOME` isolation. Clean public datasets start under `results/` with the completed `CODEX_HOME`-isolated `n = 3` `pilot-3way-v0.6.0` flagship benchmark (`LOCAL-05`, `results/pilot-3way-v0.6.0/`, 144 runs: `31/48 -> 40/48 -> 43/48` overall [`+12/-0` vs. baseline], `22/36 -> 30/36 -> 34/36` on `origin: real_work` OSS, `26/48 -> 37/48 -> 42/48` strict `wc -w`, `RW3` test tampering `8/11 -> 0/23`, Opus `-31.6%` words / `-6.9%` USD under `D-OPU-4`, with Opus `SE2` Stage 2 `8/9` semantic failure disclosed honestly).
- Preserve case, prompt and evidence snapshots supporting recorded results. Keep original `W1`–`C2` cases immutable for `v0.1.0` vs. `v0.2.0` comparison; never repair old evidence in place to make a verdict pass.
- Validation proves record consistency, not artifact correctness. Do not weaken an acceptance criterion or relabel a failed run to make results look better.
- Run `python3 -B scripts/check.py` after changes to cases, gates, results or tooling. Add focused tests only for concrete integrity risks.
- Keep the implementation dependency-free unless a demonstrated need justifies an addition. Never commit credentials, personal workstation paths, local dotdir contents, or undisclosed private benchmark inputs.
